# Hardened combined lab release — November 5

The combined JA keypad / JC OLED image now discards a block after keypad
overflow and stops with a diagnostic instead of polling busy status forever.
The public AES key and 32-hex-digit input format are unchanged. Optional
UART output uses JD1; no adapter is needed for the OLED demo.

## Changes and checks

- Firmware checks overflow before consuming an event and again after ACK,
  including the final digit. Recovery shuts the display down, waits for key
  release, clears stale events, and restarts with an empty block.
- Six bounded status waits cover AES, OLED and UART. On timeout, RAM 0x1030
  holds code 1–6 and an intentional unsupported `ebreak` halts the CPU (LD7).
  RAM 0x1034 counts overflow recoveries. Boot clears both diagnostics.
- Test 22 now checks a third full ciphertext and all its pixels/UART bytes
  after orderly shutdown/restart. Test 24 injects a real mailbox overflow
  and all six status faults. Test 25 checks the actual four-window response
  mux, invalid addresses, strobes and reset cancellation at waits 1/5.
- Test 26 runs ten independently calculated .NET AES vectors at each of
  two bus delays: 20 complete blocks and 660 decoded UART frames. It checks
  RAM contents and the OLED snapshot for each result. Test 22 separately
  checks the physical SPI pixel stream against an independent glyph model.
- All 20 original simulation tops passed again locally in Vivado 2025.2.
  See `evidence/release_regression_2026-11-05/summary.txt` in this package,
  or the per-test logs in the repository.

## Measured memory and execution

The GNU assembler/linker emits **680 bytes of code** in the **4096-byte ROM**.
The shipped HEX is padded to all 1024 ROM words. Firmware uses **56 bytes of
RAM**: 16-byte key-label lookup, 16-byte plaintext, 16-byte ciphertext and two
4-byte diagnostic words, addresses 0x1000 through 0x1037. It uses registers
for working state and return addresses; there is no stack or C runtime.
The hardware still instantiates the full 4 KB ROM and 4 KB RAM.

Test 26 measures **60 clocks** at WAIT_CYCLES=1 and **75 clocks** at
WAIT_CYCLES=5, from the successful AES START store to the final completed
ciphertext-word load. At 100 MHz these intervals are 0.60 and 0.75 microseconds.
This excludes key/plaintext writes, input typing, pixel formatting, OLED
transfers and UART. AES-only latency remains 11 clocks from the core tests;
do not label these different measurements as a software speedup.

## Implementation and evidence

The release targets xc7z020clg484-1 at 100 MHz. The matching implementation
summary, routed timing, DRC, pin and utilization reports are under
`evidence/display_hardened_2026-11-05/`. A source hash manifest binds HDL,
firmware, constraints and test data to these results, normalizing CRLF to LF
so Windows Git line endings do not create false mismatches. The ZIP also
contains an exact-byte per-file SHA-256 manifest. The earlier published ZIPs
are preserved.

The routed result is **setup WNS +0.146 ns, hold WHS +0.132 ns**. DRC has no
errors or critical warnings; the known PL-only ZPS7-1 warning remains.
Utilization is **3565 total LUTs, 2511 flip-flops, two RAMB36 blocks and zero
DSP blocks**. One LUT is used as an SRL. ROM and RAM both remain BRAM-backed;
no latches were inferred. These are local Vivado 2025.2 results, not lab-PC
implementation measurements.

All six combined tests also passed from an independently extracted lab ZIP.
The final package's RTL, ROM, vector data and benches are compared byte-for-byte
with that tested extraction; later packaging changes affect documentation
and manifests only. Extraction evidence is saved separately in the repository
under `evidence/release_extract_2026-11-05/`.

Cleanup removed **65 ignored compiler-cache directories, 57,540,356 bytes
(54.9 MiB)**. It preserved source, projects, published ZIPs, bitstreams,
checkpoints, reports, saved photos and waveform files. `cleanup.json` records
the removed relative paths. No tracked source file was deleted.

## What the lab still needs to establish

The user's independent keypad/AES and OLED pattern demos passed physically
on November 4. This hardened combined image has **not** been physically
verified. Follow [the combined guide](../NEXT_LAB_COMBINED.md), the
[ten-block reference sheet](lab_ten_blocks.md), and the
[optional UART side test](../LAB_UART_OPTIONAL.md). Lab Vivado 2020 must
independently pass simulation and timing when generating its own image.

Limitations: a bus that never returns READY has no hardware watchdog;
timeouts cover completed reads with stuck status. The one-entry keypad
mailbox is not a FIFO; overflow is detected and the partial input discarded.
The fixed public key, raw single-block AES and lack of zeroization or
side-channel protection make this an architecture demonstration, not a
production secure-message system. A software AES performance baseline,
course report/slides and final physical evidence remain separate work.
